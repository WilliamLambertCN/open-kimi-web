# 用量定价自动匹配与滚动性能 v2 计划

日期：2026-09-29。兼容基线为官方 Kimi Code 2.1.1 和当前用量统计 v1。

## 目标

- 刷新价格目录后，为统计中每个已确认的真实模型 ID 自动生成价格候选。
- 用户在一张清单中审核全部建议，并通过一次确认原子保存；不要求逐模型搜索和保存。
- 手动映射和手动四类单价始终优先，刷新目录不得覆盖它们。
- 随包提供可离线使用的 OpenRouter 公共价格快照，联网刷新失败时仍可匹配和估价。
- 手机与桌面的长模型列表保持顺畅滚动，模型多时也能到达、筛选和修正任意条目。

## 自动匹配规则

1. 已保存的手动映射或手动单价直接生效，不生成替代建议。
2. 完整模型 ID 或目录键相等时使用精确匹配。
3. 对大小写和 `/`、`:`、`_`、`.`、`-` 分隔差异做标准化后匹配。
4. 对供应商前缀存在与否、已知渠道后缀及日期、`latest`、`preview` 版本后缀做受限归一化。
5. 其余 ID 按有效词元、公共前后缀和编辑距离评分，选择稳定排序后的最高分候选。
6. 目录非空且模型 ID 有效时必须返回一个建议；低置信度必须明确标记，不能显示成精确匹配。
7. 相同供应商线索和 OpenRouter 的完整模型 ID 提高得分；同分使用目录键稳定排序，避免刷新后漂移。
8. 匹配结果提供候选目录键、模型 ID、来源、匹配方式和置信度；不得用别名代替真实模型 ID。
9. 每次请求为唯一模型 ID 建立索引和结果缓存，不能让每条用量记录遍历完整目录。

匹配只用于当前公开价格的 API 等值估算，不推断历史真实渠道，也不把未确认身份的记录自动定价。

## 内置价格目录

- 使用 OpenRouter 公共模型接口生成随包快照，保留模型 ID、名称、四类单价和可验证的阶梯价。
- 快照记录固定来源 URL 和抓取时间，不保存未知上游字段、请求凭证、用户配置或用量数据。
- 提供可重复运行的更新脚本；生成 JSON 保持机器生成格式，不受手写文件行宽约束。
- 在线刷新继续合并 models.dev 与 OpenRouter，并在 UI 中展示来源。
- 刷新失败保留最后成功目录；首次离线使用内置快照，不退回仅覆盖少量模型的手写列表。

## 批量审核与保存

- 价格接口返回当前统计模型的自动建议，刷新目录后前端立即重新获取建议。
- 审核清单显示历史模型 ID、候选模型、来源、四类价格、匹配方式和置信度。
- 默认选择全部建议；用户可取消单行、搜索模型，或用现有编辑器修改个别候选。
- 一个“确认并保存全部”动作提交选中映射；服务端先验证整批，再以一次配置写入原子保存。
- 任一项目无效时整批失败并返回可读错误，不能只保存一部分。
- 现有单模型编辑器保留为后续修正入口，手动覆盖状态必须清楚可见。

## 滚动与渲染性能

- 手机端使用统计面板作为唯一纵向滚动容器，取消分布、明细和趋势文本的嵌套纵向滚动。
- 桌面仅在表格确需固定高度时保留内部滚动，避免滚轮在多个容器之间切换。
- 大模型列表采用分批渲染或等价窗口化；初始 DOM 规模不随全部模型数线性膨胀到数千单元格。
- 屏幕外区块使用浏览器原生布局与绘制隔离，并为跳转时保留合理的占位高度。
- 批量审核表按历史模型数渲染，不为每一行创建包含完整公共目录的 `<select>`。
- 价格目录搜索继续按需显示最多 200 个结果，并能通过完整 ID 或目录键找到后部条目。
- 不在 `scroll`、`touchmove` 或 wheel 回调中同步重建统计视图。

## API 变更

- `GET /__open-kimi-mobile/usage/pricing` 增加针对查询模型 ID 的建议结果。
- `PUT /__open-kimi-mobile/usage/pricing` 保留单项形状，并新增 `{mappings:[...]}` 原子批量形状。
- 批量项使用真实模型 ID 和目录键；不得接收路径、别名、页面 token 或供应商凭证。
- 响应保持字段投影，不返回本机路径、历史正文、旧别名映射内容或上游未知字段。

## 验证

1. 匹配测试覆盖精确 ID、供应商前缀、分隔符、日期、渠道后缀、低置信度和稳定同分排序。
2. 批量保存测试覆盖全成功、非法单项整批回滚、重复模型、手动优先、重启持久化和刷新保留。
3. 使用 48、200、500 个虚构模型测量初始 DOM 数、渲染耗时和滚动期间长任务。
4. 桌面 wheel、手机触摸和键盘均可到达末项；长 ID 不横向撑开页面。
5. 按官方原版基线验证短、中、长内容，360/390/768/1440px，浅色、深色及五套现有主题。
6. 运行受影响 ESLint、定向 UT/IT、手写文件 130 字符检查和 `git diff --check`。

实图与性能验收使用虚构模型和用量数据，不读取真实会话、价格映射、账号或凭证。

## 完成标准

- 用户刷新后能看到完整的自动建议列表，并通过一次确认保存选中映射。
- 任何已确认模型 ID 在非空目录中都有候选，低置信度和来源表达准确，手动设置不被覆盖。
- 离线首次打开即可使用随包 OpenRouter 快照；联网刷新失败不会清空可用价格。
- 500 个虚构模型下，手机主滚动不会被嵌套容器截获，初始 DOM 保持受控且无持续长任务。
- 自动化、实图和交互验证均通过后，才把功能标记为完成；编译或测试通过不能代替视觉验收。
