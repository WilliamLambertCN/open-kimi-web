# 长会话与 Side Chat 流式性能验收

日期：2026-09-28。兼容基线为 Kimi Code 2.1.1。
对照源码为第一批归档修复后的 `fced26e`；本次修复纳入 `v2.1.1-r2`。

## 修改范围

- 页面增强、工作区置顶、归档删除、供应商表单与统计入口的 observer 只处理相关区域变化。
- 首次加载、接口数据刷新、控件插入/替换/移除、语言切换、composer disabled 和媒体切换继续生效。
- 提醒 observer 只响应主应用运行态、待处理控件和路由变化。
  Side Chat 内容及主应用外的同名 composer/topbar 不再重置提醒计时器。
- Side Chat 跟随底部的 setter 不再重复读取 scrollHeight/clientHeight。
  使用原生赋值后的位置识别延迟程序滚动事件，避免下一批内容增长导致错误退出跟随。
- 保留用户滚轮、键盘、触摸、滚动条定位，以及普通非底部程序定位；新侧聊容器独立维护状态。

## 确定性回归

- 真实 jsdom MutationObserver 使用回调内断开保护，验证无关流式更新被过滤且相关增强最终收敛。
- 页面增强与工作区脚本：500 条历史，主消息和 Side Chat 各 20 个独立追加批次，
  旧版合计 280 次 document 查询，新版为 0。
- 归档与供应商各自验证长历史下消息更新不扫描无关区域，相关按钮、行、容器或模型行变化仍能增强。
- 统计入口：20 批双栏更新，从 40 次入口查询降为 0；迟到的入口锚点和被移除按钮可以恢复。
- 提问控件出现后再追加 20 批 Side Chat 内容，提醒计时器从 21 次安排降为 1 次，提醒正常显示。
- 延迟滚动回归先在旧实现上失败，再验证浏览器式 clamp、迟到的 scroll、普通程序定位与滚动条操作。

## 隔离 Chrome

使用官方 2.1.1 CSS、当前全部 15 个注入脚本和虚构 DOM，无真实会话、凭证或付费模型调用。
测试服务仅监听回环地址，Chrome 使用独立临时 profile。

| 场景 | 对照结果 |
| --- | --- |
| 500 条主历史、50 条侧聊历史、20 批双栏流式追加 | document 全局查询 280 → 0 |
| 旧守卫的延迟 scroll 事件 | top 停在 3838；bottom 增长至 4264 |
| 新守卫的连续输出 | 每批 top 与 bottom 相等 |
| 向上阅读后继续输出 | 阅读位置保持 |
| 手动回到底部后继续输出 | 恢复跟随，top/bottom 均为 4398 |
| 官方浅/深色与五套氛围主题 | 7 套外观分别验证桌面和手机，共 14 组 |
| 1440px 桌面/500 条历史，390px 手机/4 条历史 | 关键区域尺寸与优化前一致，初始截图一致 |

程序滚动与延迟事件测试验证实际 Chrome 行为。截图仅用于局部布局回归，不能替代官方应用的完整端到端验收。
没有使用短时间墙钟差异宣称整体加速倍数；结论是已消除确定的重复查询和错误滚动状态转换。
本轮未改生产 CSS、官方折叠偏好、消息数据或官方历史渲染实现。
