# 每次模型调用显示速度、侧边聊天选择模型 · v1

## 目标与范围

用户要求每个模型请求结束后显示 TTFT、TPS，并为侧边聊天添加可选模型。
本文件是按当前需求制定的本地执行基线；默认假设由实现者明确列出，不代表用户逐项批准了设计细节。
初始范围不含提交发布；用户已追加授权，按[2.5.2-r3 发布计划](request-metrics-2.5.2-r3-release-v1-plan.md)执行。
下方“不提交／不发布”保留为阶段事实；本轮不升级用户 CLI 或重启生产。

## 已核对的官方行为

- 以正式 npm `@moonshot-ai/kimi-code@2.5.2` 和对应 tag 源码为准，不以其它分支的新源码代替。
- TranscriptStep 提供 `usage.output`、`llmTiming.llmFirstTokenLatencyMs` 和 `llmStreamDurationMs`。
  官方已保存这些数据，但普通 Web 界面不显示，仅桌面 debug 界面可见。
- 官方 timing 从当前成功尝试的构建起点计 TTFT；流式耗时从首段返回到流结束，不含后续工具执行。
  重试会重新开始计时，不能从浏览器收包时间或整个 turn 的总耗时推算模型速度。
- 侧边聊天由正式 `POST /api/v1/sessions/{id}:btw` 创建 agent，仍属于原会话。
  正式 prompts 接口允许同时提交 `agent_id`、`model`、`thinking`，只修改目标 agent。
  session profile 的 `agent_config` 修改主 agent，不能用于本功能。
- 官方侧边聊天每次发送默认再次传主模型与主思考档位。独立选择必须在目标 agent 的原生发送中生效，
  不能只改 UI，也不能全局替换所有非 main 请求。

## 实现

### 显示真实 TTFT、TPS

- 分成独立的数据投影、被动传输观察、显示文件，登记官方资源清单；自定义 `--web-dir` 不注入。
- 只观察官方已消费的 transcript 最近页、历史页及正式 WS reset/ops；不另读日志、扫描磁盘、下载完整历史或轮询。
- 仅保留精确会话、agent、turn、step 身份和数值，不保留 frame、正文、工具参数或凭据。
  缓存最多四会话、每会话十六 agent、每 agent 两千条 step/turn/删除标记；响应附加文本解析最多 2 MiB。
- 每个已结束 step 对应一次模型调用，指标紧贴该 step 自己的原生回复或工具调用块，每处只放一行。
  不再跨 step 汇总到最终回复；历史页、重连与实时消息按相同身份规则重新显示，不要求当时已经开启增强。
  找不到该调用的精确锚点时不转挂到后续回复，不按消息正文、顺序或标题猜测。
- 按用户在同次请求对账后的最新要求，TTFT保持原值，TPS改为输出token除以本次模型请求总耗时，
  即 `usage.output * 1000 / (llmFirstTokenLatencyMs + llmStreamDurationMs)`，显示“平均 TPS／Avg TPS”。
  分母包含等待首段，不包含工具执行、整个提问的其它调用或未记录的重试时间；不宣称是模型纯解码速度。
  官方首段包含流式思考、正文及工具调用，不把空role当首段；思考token不重复加。
  两项计时均有效、求和安全且总耗时至少50 ms才计算平均TPS；缺值不当作0，TTFT仍可单独显示。
- 同一行新增“缓存命中／Cache hit”，显示两位小数百分比：
  `inputCacheRead / (inputOther + inputCacheRead + inputCacheCreation) * 100`。
  新写入缓存的输入计入分母但不算命中；不包含输出token。仅明确非负安全整数且总输入大于0时计算，
  缺字段、非法值或求和越界显示“—”，明确0命中显示0.00%；无计时的旧消息仍可显示有效缓存率。
  不新增API或数据存储，继续使用官方已消费的逐step usage；主聊、侧聊及历史使用同一规则。
- 本次只改公式、双语文案和已有统计行；定向测试补总耗时、缓存分母、缺值及实时更新，
  用准确2.5.2隔离后端实际返回缓存用量，并补双端三主题、窄屏长短内容的实图及几何检查。
  下方首段后TPS及先前平均方案均保留为阶段记录，当前口径以本节和最新验收记录为准。
- 缺值、错误值、零耗时及失败/取消保持明确的不可用或未完成标记，不伪造零值；不展示运行中的最终速度。
  保留晚到 timing、分页、重连、reset、删除、回退和旧请求门禁。
- 准确 2.5.2 会把同一提问的多次调用合成一个回复容器，frame ID 不能定位其中各次调用。
  使用受版本及完整结构校验保护的静态展示适配，透传 step ID 并使用官方逐 step 计时位置。
  过程调用的计时只附在该 step 的原生工具／思考条目上，不成为打断工具分组的独立条目；
  原生组内渲染及重试详情同步附带轻量位置，折叠、汇总、虚拟化仍由官方处理。
  没有可渲染assistant frame或被官方去重的调用不造孤立行，不连续叠到前一工具或回复下面。
  不开启桌面或后端 debug，不访问 Vue 私有状态，不复制官方合并、折叠或虚拟列表算法。
  全部适配点匹配才返回修改后的 JS，缓存使用独立修订标识；不改官方缓存原文件或后端数据。
  不支持的版本或结构不猜测、不恢复旧的末尾堆叠，正文继续原样显示。
- 指标按当前会话、agent 与原生逐 step 位置的精确身份插入，保留官方复制、时间、选择、滚动及虚拟列表。
  侧边聊天的指标必须先确认 agent 身份，不按标题、文字或用户消息顺序猜测。

### 侧边聊天选择模型

- 双端均在原生侧边聊天输入区添加小型选模入口，复用现有模型列表的搜索、供应商和主题样式。
- 默认跟随主模型；只有用户明确选择时，才对该侧聊的下一次原生 prompts 请求写入 model。
  切回跟随后不补写 model/thinking，让原生行为继续生效。
- 读取原生 panel 保存的 typed btw payload，联合校验 tabs 数量、唯一激活项与可见 DOM 的 panel tab ID。
  tab ID 不是 agent ID，不按标题猜测；切会话先失效，待当前会话原生 panel 写入后再绑定。
  不同侧聊、主聊天、子代理互不串模型；身份不明确时禁用并解释，不靠 Vue 私有实例或压缩符号绑定。
- 只改原始请求的选模字段，保留原生请求、附件、取消、鉴权、信任、会话锁、错误与草稿恢复行为。
  不调用 config 写入，不改全局 secondary_model，不重发或自动重试发送。
- 模型列表以官方 config/models 为准，支持加载、错误、重试、无模型、单模型、失效模型、取消和键盘焦点。
  选择仅留当前页面内存，刷新恢复默认，不承诺侧边聊天关闭后的持久恢复。

## 默认假设与边界

- “请求”指模型的一次调用，不是网页资源、REST 或工具执行请求。
- TTFT 采用官方含构建阶段的首段延迟，不宣传为纯模型服务端时间。
- 本轮首先验收准确 2.5.2。旧历史没有 timing 时无法事后还原，不伪造指标。
  官方去重后没有独立回复或过程可挂的调用不转挂其它消息；保留原生内容去重，不为显示统计复制正文。
- 本轮是网页展示和发送增强，不新增稳定公共 API，也不修改官方后端或启用通用 debug。
- 仿真屏幕不等于实体手机或系统软键盘；任何未验证范围应在结果中说明。

## 逐调用展示与平均 TPS 修正 · 2026-11-12

本节保留当时的逐调用布局修复与平均吞吐尝试；用户随后否定把TTFT计入TPS，当前公式以实现节及末尾澄清为准。
下列21.3平均值、全套和包检查均属该阶段证据，不作为恢复首段后TPS口径的新验收。

### 修正与原因

- 官方把同一提问中的多次模型调用合并到一个回复容器，旧实现把容器误当成单次调用边界，
  所以统计堆在最后。现在透传精确 step 身份，在该调用自己的回复、工具或思考过程下只放一行。
- 过程统计附在原生条目上，不成为独立条目打断 activity 分组；展开、收起、整轮折叠和重试详情沿用官方行为。
  无可渲染 frame 或正文被官方去重时不另造行，不转挂到前一条或后一条；不为统计复制正文。
- 历史、分页、重连和虚拟列表重新挂载使用同一规则，不要求当时启用增强；原记录缺 timing 时仍显示不可用。
  主聊天和侧聊按 session／agent／step 隔离，不新增历史读取、轮询、全文下载或配置写入。
- 旧 TPS 只除以首段后的 stream 时间，排除了等待首段的时间，不能与服务商未说明的统计口径直接比较。
  现在明确显示“平均 TPS”：output／(TTFT＋stream)，计至模型流结束，不包含工具或整个提问的执行时间。
  output 不重复加 reasoning tokens；任一计时缺失、非法、求和不安全或总时长小于 50 ms 时不估算。
  未取得用户同次真实请求的服务商记录，不能声称已对齐其 40–50 tok/s，也不把平均值当纯解码速度。
- 静态适配仅支持准确官方 2.5.2，所有语义结构和数量匹配才整体生效；不依赖固定压缩变量或文件 hash。
  入口与 modulepreload 使用独立 step-metrics-v2 资源路径，不修改官方缓存原文件或开启 debug。
