## 事件：供应商选项显示已选但预设保存丢失

- 影响：从预设添加供应商时，显示的模型能力、思考档位及顺序可能未落库。
- 触发条件：官方 2.6.1 原生未标脏的预设表单，提交 `providers:import_catalog` 而不是完整模型 POST。
- 根因：旧增强只合并完整模型 POST／PUT；旧测试直接提供完整 models，漏测原生保存分流。
- 证据：准确官方表单实际请求不含 models，独立后端回读不符；完整模型 POST 可正确持久化。
- 修复：仅在增强表单保存点击时复用原生输入事件改变提交分流；匹配失败先拒绝，不静默漏存。
- 回归验证：上述定向测试及一次必要的真实后端／浏览器补验；默认配置及唯一真相源边界不变。
- 运维动作：更新后手动重启旧 launcher 并刷新。过去已丢失的选项需显式重选保存，不批量迁移。
- 剩余边界：实体手机及其它未验证官方版本不保证；本次不修复官方上下文预算或现场慢连接。
