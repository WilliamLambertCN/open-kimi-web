# 低带宽大会话打开修复 v2

## 本轮范围

- 解决 Open Kimi Web 在低带宽链路打开大会话缓慢或失败的问题。
- 原始数据只读，在隔离副本中测试，不发送模型请求，不更改原始数据或生产服务。
- 不提交 Git、不推送、不发布；不升级官方 CLI 或修改网络。
- 测试正文、截图、会话标识、路径和凭据不进入版本控制或公开文档；公开记录仅保留必要工程证据。

## 已核对的实现事实

- `packages/launcher/src/httpProxy.mjs` 已有流式 gzip 及 120 秒上游 socket 空闲超时，不能把新加 gzip 当修复。
- `packages/launcher/src/responseCompression.mjs` 不缓冲整响应；保持其背压、鉴权、Range、SSE、取消边界。
- `packages/launcher/src/wsProxy.mjs` 双腿 64 MiB 消息上限，浏览器侧未协商压缩，桥接发送缺背压控制。
- 准确官方 npm 2.4.1 主界面每页 10 turns；cold transcript 先完整 fold wire，再分页。
- 每页关联实体仍全量返回，单 turn 没有字节预算；官方请求有 30 秒整体 timeout，解析和渲染还要处理解码后正文。
- 官方初始 WS reset 的 tailTurns=0，但仍带关联实体；live seq catch-up 与 cold 重建不能按旧 2.1.1 fixture 推断。
- running subagent 缺 parent 信息时，官方可自动回溯旧页。不能靠屏蔽它、丢弃消息或截断日志伪造优化。
- OKW 时间戳增强已避免 transcript clone，大正文不另行 JSON.parse，不盲改该模块。

2. 离线统计 wire 类型、大小、turn 与关联实体，检查 cron、待执行任务和 fork/restore 链；
   不打印正文、标识、路径、标题或命令。
3. 复用经身份校验的官方 2.4.1，建立隔离 home、虚构工作区与测试 token。
   历史记录可能包含动作：先用只读 cold API；浏览器恢复测试前须确认任务不会执行、工作区不能触及真实文件，
   并使用无外网凭据的环境，拒绝模型调用和执行操作。
4. 测 detail、最近页、上一页、plan/用户消息等实际请求；记录 TTFB、HTTP 编码前后字节、耗时、RSS、状态/错误来源。
   同一请求分别官方直连与真实 createLauncher，不把 wire MB 当传输 MB。
5. 使用准确官方完整 app 与后端响应建立无需恢复生产任务的可控重放；REST/WS 内容仅在内存中使用，断言真实 wire shape。
   限速为所有并发共享 625,000 bytes/s，并覆盖 WS，不以每个请求独享 5 Mbps 或只 HTTP 的 CDP 设置代替。
   记录超时/重试、WS 帧及 seq、最新内容可见与输入可操作情况，比较 bare/enhanced。
6. 根据已发现的瓶颈，计划补 200/300/400/500 MB 虚构 wire、巨大单 turn/实体样例，不重跑无关 UI/安装矩阵。

## 2. 按实证实施最小修复

1. 优先在传输层修复已命中的缺口：若 WS 未压缩/发送积压是主要问题，在 `wsProxy.mjs` 做可协商压缩和有界背压，
   保留精确消息/顺序/鉴权/关闭语义及无扩展客户端兼容；不直接取消 64 MiB 安全边界。
2. 若问题是 HTTP 字节量/官方超时，先验证现有 gzip 的实际协商和背压，修复证实的传输错误；不统一无限延时。
   若必要减少官方请求页尺寸，只使用正式 page_size/cursor，保留完整 turn、分页与最新消息，不改业务实体或复制状态管理。
3. 若瓶颈位于官方 cold fold、clone/解析或单 turn 实体大小，明确不能凭 DOM 补丁解决。
   记录最小上游修复点；需要超出外层轻量边界时先更新计划并说明，不偷偷维护第二引擎、缓存数据库或改写官方 bundle。
4. 根据测量选定实际补丁后把结论与范围同步到计划再编辑。新增模块按 officialPresentation 清单约定登记。

## 实测收敛与已选补丁（2026-11-06）

- wire 总量并非首屏下载量；隔离测量区分正文、压缩传输和恢复阶段。
- 共享 625,000 bytes/s 下，准确 2.3.1 完整 app 重放同一 cold 响应；两组均经真实 launcher/gzip，最近页未发生 HTTP 超时。
  此阶段使用虚构 WS 握手，不代表真实恢复通过。
- 官方默认折叠时约为数千 DOM 节点、数百毫秒的最大长任务；OKW 默认展开后增至数万节点、秒级长任务。
  增强版显式使用官方折叠后，节点数与最大长任务接近原生基线，首内容出现时间缩短。
  均为单次隔离样本，不声称所有设备或原现场已修复；未截图或保存真实响应，媒体/外网请求被阻断。
- 最小 UI 补丁：`foldingDefaults.js` 无偏好时采用官方折叠值 `1`，保留已有值（包括 `0`）。
  旧版本已写入的 `0` 无法区分默认和用户选择，不静默迁移；用户可在官方设置开启工具活动折叠。
  不改 turn、输出、实体、分页、上游 bundle 或主题布局；定向 UT 验默认与显式偏好，干净 UI 验原生展开可用。
- WS 验证在无网容器中使用隔离派生副本；只读挂载并使用 tmpfs，不恢复生产会话。
  测试前未发现待执行任务或通知，hooks/MCP 等来源仍需核对；报告仅保留协议层必要证据。
- 准确 2.4.1 的普通订阅、无 since 的 v2 零 turn reset 和 live seq catch-up 经隔离后端验证。
  显式 since=0 返回包含历史 operations 的更大响应，非准确 UI 的 cold 默认请求；未复现该样本的超时或超大帧拒绝。
- 第二项最小补丁：仅增强 UI 的精确 2.3.1/2.4.1，对 main 的无 before/after、显式 page_size=10 的 GET
  transcript 改用官方 page_size=1；不改响应、实体、seq、cursor、历史页、子代理或 WS，也不额外探测/唤醒会话。
  自定义 UI/未知版本/不同页数保持透明；严格匹配路径和单值查询，不把参数歧义规范化成另一请求。
- 准确 2.4.1 实际响应候选测试中，最近 1 turn 的压缩传输小于旧页；原生按钮加载更早的 turn 后，已加载 ID 完整且无重复。
  最近页内容可见时间短于同条件的增强 UI；候选测试含冷静态资源，与其他环境的时序不可直接比较。
  短首屏上滚未自动触发官方 sentinel，原生“加载更早消息”按钮可用；不为此覆盖 Vue 滚动状态或冒称自动分页已通过。
  这些是 cold 响应重放，仍须验证改后产品请求链与真实 cold→reset→live seq，不能以 QA 参数替换当产品实现。

### 事件：低带宽打开工具密集大会话缓慢

- 影响：低带宽链路打开大会话缓慢或失败；本轮只复现并修复其中可确认的加载／渲染回退。
- 触发条件：增强 UI 无折叠偏好、最近数轮含较多工具输出；主会话初始请求最近 10 轮，关联实体仍全量返回。
- 根因：OKW 将工具活动默认设为展开，增加大量 DOM 与同步工作；同时首屏取 10 轮而非先取最新 1 轮。
  整个 wire 总量不是首屏下载量；现有 gzip 有效，未发现本样本 WS 超大帧或 HTTP 超时。
- 证据：同版真实响应的节点数从约数千增至数万，最大长任务从数百毫秒增至秒级。
  2.3.1 在共享限速单次隔离测量中，修后 page_size=1 最近页的传输小于旧 page_size=10 请求。
- 修复：仅无偏好默认折叠，按精确前端版本将无 cursor main page_size=10 代理为 1；保留原生历史页、正文、实体和 WS。
- 回归验证：标准门禁、准确版本真实响应、真实 2.4.1 浏览器 cold→live／旧页／输入／保持及独立协议重连通过。
  旧测试检查默认值和压缩／透传，没覆盖本轮真实工具密集分布；新增偏好与路径边界测试并补真实浏览器证据。
- 运维动作：需使用本地修改后的 launcher，重启该 launcher 并刷新页面才生效；本轮没有替用户执行生产重启。
  旧浏览器已有展开值不覆盖，需在官方设置手动开启工具活动折叠；无需删除会话或清官方缓存。
- 剩余边界：原现场的完全打不开仍未复现／复测，巨大单轮和关联实体仍可能慢；未保证任意 500 MB 会话可用。
