# 子代理候选池与描述编辑 v1

## 目标与范围

在现有双端子模型设置旁添加候选池管理入口，继续使用官方配置作为唯一真相源。
展示已有全部候选、默认候选和每项给主代理看的选择说明；支持从已配置模型手动添加候选、编辑说明和默认候选。
提供两套可修改的说明模板：大哥负责复杂推理与疑难问题但较慢，小弟适合清晰简单的执行任务但推理较弱。
模板是用户偏好，不是测速、能力保证或固定派发规则；不自动分配角色、删减已有池或改思考档位。

## 接口边界

- 精确官方 npm 2.6.1 的 GET／POST `/api/v1/config` 使用外层 `secondary_model`、内部 camelCase 字段。
- `models` 是别名到说明的映射，`defaultModel` 必须属于池；只有一个候选时官方不暴露模型选择参数。
- `defaultEffort` 是整个池共用的覆盖值，保留并按最新候选集校验，不能悄悄清空不兼容的档位。
- 官方 REST 配置合并嵌套映射，不能通过省略某键删除候选；本轮不提供单项删除，不先清空再重建。
- `primary` 不假定为特殊继承选项，只展示官方实际配置的普通别名。跟随主模型仍走既有独立控件。
- 保存前重读，按用户实际修改的候选合并，发现同项或默认选择并发变化时报错；不覆盖无关字段或新增的其它候选。
- POST 后回读核对默认、说明、原有候选与思考设置；失败保留草稿，不保存 token 或配置到浏览器存储。

## 界面与实现

- 桌面在“智能体与会话”的官方子智能体区加入入口；手机在现有子模型入口旁加入相同入口，不替换原生选择器。
  完整 2.6.1 页面确认子智能体不在通用页；旧版若在通用页仍按实际子智能体段定位，不靠固定 tab 索引。
- 复用现有模型搜索、供应商筛选、身份展示和主题变量，使用同一个编辑器适配两端，不扩展官方前端状态管理。
- 候选说明使用带可见标签的 textarea，模板按钮只在点击时改当前草稿，切换语言不翻译用户已填的说明。
- 添加候选复用现有模型选择 UI；保存是显式动作，加载、选模板和取消均不写后端。
- 使用原生 modal dialog、表单与 radio，保留 Escape、焦点恢复、中文输入法和手机滚动；长别名和说明不撑宽页面。
- 新逻辑独立资源登记，观察器只处理设置相关 DOM，流式聊天不触发全页扫描，注入保持幂等。

4. 在准确官方完整页面比较原版基线与增强版；覆盖手机竖横屏、桌面、短长名称、已有多候选和现有主题。

### 事件：Windows 全量测试清理超时及随机 HTTP 失败

- 影响：全量测试无法通过；更新、安装取消或重启收尾在负载高时也可能无法确认子进程树已停止。
- 触发条件：默认并发运行，清理需先启动 PowerShell；系统动态端口范围含 Fetch 禁止访问的端口。
- 根因：PowerShell 启动、即时编译及快照清理共用三秒预算，原来单独运行的测试未覆盖启动开销。
  安装入口另有两次独立 Node/npm 探测；版本 fixture 在断言阶段额外编译程序，注册表 fixture 多次启动 PowerShell。
  HTTP fixture 依赖系统分配端口，碰到禁止端口时直接报 `bad port`，Cron 将其转为 `upstream-unavailable`。
- 证据：全量分段诊断确认 PowerShell 启动与即时编译占用了清理预算，安装探测存在重复进程开销。
  多处 HTTP 失败显示 `bad port`，端口分配证据确认 fixture 不能假设系统动态范围总与 Fetch 兼容。
- 修复：直接使用固定系统 .NET Framework 编译器运行原有清理算法，临时程序用完删除，编译与执行仍共用三秒。
  PID、创建时间、句柄及后代归属校验不变，失败仍报未确认并保留锁，不按名称杀进程。
  Node/npm 合并到一次实际执行探测；编译 fixture 放在准备阶段，注册表测试用原生工具准备和清理其专属值。
  HTTP fixture 在动态／私有高端口范围监听；不修改系统端口范围，也不复制或放宽 Fetch 的禁止列表。
- 回归验证：新增四棵自有进程树并发清理、独立进程存活、共享截止时间、缺失编译器与特殊路径等测试。
  安装探测仍覆盖真实 npm、损坏 CLI、非法版本与非零退出；高端口 fixture 有真实并行 Fetch 和失败绑定回归。
  最终不带诊断注入的标准 UT/IT、lint、typecheck、test:pack 全部通过，超时、并发、原断言及覆盖率门槛未放宽。
- 运维动作：未重启生产服务或升级官方 CLI；已停止本轮确认归属的遗留测试进程，删除其临时目录。
- 剩余边界：本轮标准门禁实测环境为 Windows；现有平台专属跳过不表示对应平台已在本机验证。

## 2.6.1-r4 发布流程

发布已验收的候选池功能及本轮 Windows 清理、安装探测和测试 fixture 修复，不追加新版官方适配。
兼容基线仍为准确官方 `2.6.1`，保留 `2.6.0`；`2.6.2` 和 `2.7` 的更新研究不等于兼容验收。

1. 同步 launcher、插件、当前安装命令与发布说明为 `2.6.1-r4`，保留历史版本记录。
2. 对新增版本与文档差异做定向隐私检查，核对待推历史、提交身份与实际文件；不重复已完成的实图及全量本地测试。
3. 提交并推送 develop，经 PR 和本次标准 gate 合入 main；核对准确 main 的提交身份、正文及 CI。
4. 从验证后的准确 main 标准打包，检查实际文件清单、版本及公开内容，再创建正式 tag、Release 与唯一 tgz 安装包。
5. 核对线上 tag、latest、包下载及只读更新发现，发布后同步 main 回 develop。

不关闭分支保护，不替换旧 tag 或清理旧包，不发布 npm registry。
本轮本地全量验收结果见上文；PR、main CI 和线上检查在实际发生后分别核验，未记录不视为通过。
正式发布状态以 [Release](https://github.com/WilliamLambertCN/open-kimi-web/releases/tag/v2.6.1-r4) 为准。

## 交付边界

不升级官方 CLI、不修改用户 config.toml、不重启生产服务。用户更新后自行重启旧 launcher 并刷新页面。
实体触摸设备、软键盘和实际付费子代理派发未验证，不用浏览器模拟结果替代这些结论。
