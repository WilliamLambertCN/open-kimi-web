# 手机消息目录 v1 实施计划

## 目标与范围

开始时间：2026-11-08T21:54:00+08:00；沿用最初进入计划模式的时间，包含等待与恢复。

给手机补上桌面聊天区右侧的消息目录：点一条用户消息摘要，直接跳到那段对话，不必反复上滑。
沿用官方消息身份、历史分页和跳转，不另建会话数据，不全量下载大会话。
本轮只在本地实现并验收；不提交、推送、发布、升级官方 CLI 或重启生产服务。
保留当前 develop 分支的既有改动与用户的 .tmp/。

本计划根据用户当前请求实施；工具自动退出计划模式不代表用户另行审核了具体方案。

## 界面

- 手机聊天页提供一个可发现的“消息目录 / Message outline”按钮，与顶部设置入口保持统一风格。
- 点击打开符合当前主题的目录浮层；不常驻占据手机聊天宽度，不盖住标题或挤压正文。
- 每条显示用户消息摘要；当前所在消息有标记，长摘要可换行且不会挤出按钮。
- 点选后关闭目录并跳转；关闭按钮、背景点击和 Escape 均可退出；键盘焦点限制在打开的面板内，关闭后归还入口。
- 遵从官方已加载历史范围；如果旧历史尚未加载，明确提示，不偷偷下载整个会话。
- 新会话、无消息或不适配的界面不出现无效入口；桌面继续使用原目录。

## 代码与边界

1. 核对精确官方 2.4.1、2.3.1 bundle 中 `.conversation-toc` 的挂载、稳定类名、点击语义和分页范围。
   只使用公开 DOM／正式接口；禁止 Vue 私有实例、data-v-*、构建 hash 或压缩变量依赖。
   已核对两版：mobile 为 true 时不挂载原目录，消息虚拟列表也不会为未挂载项留下精确锚点。
   不改变官方断点，不通过搜索／全选强制全量渲染，不使用高度比例猜消息位置。
2. 在 `packages/launcher/src/mobile/` 增加独立目录 Metadata、Navigate、View、Controller 与 CSS。
   被动观察官方已请求的主 transcript，仅提取有界用户目录元数据，不持有助手正文或另一份完整 transcript。
   普通 opening 用精确 turnId:input，steer 使用 frameId；按官方用户 origin 白名单排除 cron／task／系统触发。
   监听 reset／upsert／remove 保持目录有效，切换时不混用旧列表；最多缓存四个会话的短目录，不保存正文或浏览器存储。
   DOM 标题可按精确 ID 校正，不按文字猜身份；每个会话最多保留 2000 条目录，单个摘要不超过 240 字符。
   大于 2 MiB 的响应或 WS 帧不做额外解析，原生显示不截断；此时目录可能不完整，不能据此声称覆盖全部已加载消息。
   导航使用外层 `.history-row` 原生 previous／next 按钮揭示未挂载项，再对精确锚点定位；有界、可取消且逐步核对身份。
   增强代码只通过原生加载按钮显式取下一页，不自动拉全历史；跳转前解除原生 following，不改内部状态。
   到达已加载历史顶端时，官方 sentinel 可能自行预取一页；不禁止原行为，也不承诺跳转绝对没有额外请求。
   View／Controller 只提供手机打开／关闭、可访问性和必要布局；共享 locale.js，使用现有主题 token。
   不移动／克隆受 Vue 管理的节点，不改官方 bundle，不修改模型、会话内容、偏好或鉴权。
   原生相邻揭示是 O(distance)，不是公开 O(1) reveal API；若真实验证不足，明确保留未完成而非缩水成当前 DOM 目录。
3. 处理路由切换、会话卸载、断开重建、空目录、resize、已有原生／增强弹层等生命周期。
   以精确会话和原节点身份失效旧状态；不要让旧目录跳到新会话。
   观察器只关注目录及挂载／布局变化，流式正文更新不能触发全文扫描；所有 DOM 写入必须幂等收敛。
4. 在 `packages/launcher/src/officialPresentation.mjs` 的 FILES、SCRIPTS、STYLES 注册资源。
   在 `tests/it/launcher-official.it.test.mjs` 核对资源、注入次序和 custom --web-dir 不注入。
5. 计划落盘到本文件，并在 AGENTS.md 链接。
   实现与验收完成后只更新必要维护记录；README 保留预览在前、快速上手集中安装的顺序。

### 事件：手机没有桌面的消息快捷目录

- 影响：手机只能连续滚动，无法像桌面一样点用户消息摘要返回对应对话。
- 触发条件：精确官方 2.3.1／2.4.1 手机断点；消息列表还可能虚拟化，未挂载消息不在 DOM 中。
- 根因：原生目录只为桌面创建；单看当前 DOM 会漏消息，单次 smooth 调用也不能保证最终可见。
- 证据：准确包审计、原生 Chrome 对照及上述保留的失败／修后报告。
- 修复：新增手机目录与被动短元数据，复用原生分页／相邻揭示，用精确消息锚点完成定位。
- 回归验证：新增目录单测、原有时间戳联跑、完整官方 app 的 REST／WS 与主题布局验收。
- 运维动作：本轮未部署；以后采用这份代码需重启 launcher 并刷新页面，不修改会话或安装配置。
- 剩余边界：只支持已核对 DOM／协议；最多四会话、每会话 2000 项；超过解析预算的页面可能缺项。
  未验证实体手机、软键盘或任意大会话；不把虚构样例通过当成所有设备保证。
