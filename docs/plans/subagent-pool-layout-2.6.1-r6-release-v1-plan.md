# 子代理候选池布局与 2.6.1-r6 发布 v1

## 目标与边界

将双端共用的子代理候选池编辑器改成紧凑的扁平列表：候选之间只保留主题分隔线，说明输入按内容显示一至两行，
超过两行时在字段内部滚动。继续使用官方配置接口和现有草稿、模板、默认候选及保存流程。

本轮不修改候选池数据结构、默认候选、说明模板语义、并发冲突处理、保存协议、官方 Kimi 安装或
准确 `2.6.0`／`2.6.1` 兼容范围。不自动重启生产服务，不升级官方 CLI。

## 实现方案

- 弹层使用单一官方主题表面色；候选项去掉独立卡片背景、圆角和完整边框，仅用分隔线区分。
- 说明字段使用透明背景和单条底线，短内容显示一行，最多显示两行，更多内容通过字段内部滚动查看。
- 禁止用户拖拽放大说明字段；聚焦时只强调主题色底线，保留真实按钮和其它输入的可见焦点状态。
- 使用原生 `field-sizing: content`，并为不支持该属性的浏览器提供一至两行高度计算；窗口宽度变化时重新计算。
- 打开、输入模板、普通重绘、关闭和异常清理均沿用现有生命周期，不增加配置写入或额外后端请求。

## 发布

发布目标为 `2.6.1-r6`。从 `develop` 经受保护分支 PR 合入准确 `main`，在准确 main 上创建带注释 tag，
只上传 `open-kimi-web-2.6.1-r6.tgz`，不发布 npm registry。新包与更新发现全部核验成功后，
删除旧 `2.6.1-r5` Release 的 tgz 附件，保留 r5 tag 和 Release 说明。

更新不会替换已经运行的进程。用户完成更新后须自行停止旧服务，按原方式运行 `kimi web --host` 并刷新页面。

### 事件：候选池编辑器占用过多空间且色系不协调

- 影响：桌面和手机候选池中的每个候选、说明输入都带完整框和独立底色，短说明仍占固定大高度。
- 触发条件：打开包含一个或多个候选的候选池编辑器；说明越短，空白和重复边框越明显。
- 根因：候选卡片与说明 textarea 同时使用完整 surface／border，且 textarea 固定 `rows=3` 和最小高度。
- 证据：修复前样式同时声明候选卡片边框、独立背景和说明字段固定高度；完整页面可稳定复现。
- 修复：候选改为分隔列表，说明改为透明单底线字段；按内容显示一至两行，超出部分内部滚动。
- 回归验证：定向测试与完整官方页面覆盖三种内容长度、桌面／手机、Original／Nocturne 和宽度变化。
- 运维动作：更新 launcher 后手动重启旧服务并刷新；无需迁移或修改候选配置。
- 剩余边界：未在实体手机和系统软键盘上直接验收；布局不改变官方配置接口可用性。
