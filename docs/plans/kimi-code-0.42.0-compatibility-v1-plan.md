# Kimi Code 0.42.0 兼容整改计划 v1

## 状态

- 实施状态：已完成，目标发布版本为 `0.42.0-r1`。
- 发布状态：待提交、推送和打 tag；本轮不执行这些发布动作。
- 兼容边界：完整协议快照仍为 `0.41.0` 历史记录，`0.42.0` 变化按已核对接口和发布 bundle 验证。

## 目标

把官方 Kimi Code Web 与后端兼容基线从 `0.41.0` 更新到 `0.42.0`，移除已经被官方正式能力取代的
debug 删除链路，并保持手机端任务完成、审批和提问强提醒的既有行为。

## 用户可见结果

- 已归档页仍提供永久删除入口，确认后调用官方正式会话删除接口。
- 中文界面显示中文删除文案，英文界面显示英文文案。
- 任务完成、审批和提问继续触发同等醒目的手机弹窗。
- 初始空闲、切换会话、历史回放不会误触发；断线重连继续保留检测状态。
- Rive WASM 资源以正确的 `application/wasm` 类型返回。

## 实施范围

1. 将自定义归档删除请求改为 `POST /api/v1/sessions/{session_id}:delete`。
   成功响应兼容官方客户端接受的 HTTP 204 空响应和 `code: 0` JSON envelope。
2. 删除 launcher 的旧删除转发和托管后端的常态 `--debug-endpoints` 参数。
3. 继续只为唯一匹配的已归档会话行添加删除入口，并保留确认、重复点击保护和失败回滚。
4. 从与官方 `0.42.0` 一致的语言状态确定文案，覆盖界面语言与浏览器语言不同的情况。
5. 为静态文件服务增加 `.wasm` 到 `application/wasm` 的映射。
6. 更新官方 bundle 回退版本、兼容清单、契约元数据、维护说明和相关测试到 `0.42.0`。
7. 保持提醒状态机及其选择器、WebSocket 握手门控、节点去重和重连行为不变。
8. 对新增或修改的手写源码、测试、配置与文档执行 130 字符行长限制。

## 版本边界

- 默认及完整验证基线为 Kimi Code `0.42.0`。
- `0.42.0` 使用官方正式删除接口，不要求后端开启 debug endpoints。
- 若保留 `0.41.0` 兼容路径，必须按已确认的服务版本显式门控，不能常态暴露 debug 能力。
- 不修改用户会话、账号、工作区或本地 Kimi 数据。

## 验证

- 归档删除测试覆盖取消、204/JSON 成功、官方错误、鉴权未就绪、重复点击和唯一会话映射。
- 语言测试覆盖中文界面与浏览器默认语言不一致的场景。
- 静态文件测试断言 `.wasm` 返回 `application/wasm`。
- 官方 bundle 和 launcher 集成测试断言 `0.42.0` 回退版本、注入顺序及不再使用 debug 删除链路。
- 运行受影响文件的 ESLint、对应 UT、必要的 launcher official IT、`git diff --check` 和行长检查。
- 提交或发布前检查待公开 diff、发布清单、构建产物和相关提交历史中的凭证、个人路径、日志、备份及 sourcemap。

## 验收标准

- 代码和测试中不再调用 `/api/v1/debug/sessionManager/delete`，托管启动参数不再包含 `--debug-endpoints`。
- 归档删除通过官方 `:delete` 接口完成，成功和失败行为与确认文案可被定向测试证明。
- 中文界面不再出现英文 `Delete permanently`。
- 强提醒相关定向测试继续通过，既有防误触和重连约束没有退化。
- 手写改动没有超过 130 个字符的行，工作树中不包含临时测试数据或用户数据。
