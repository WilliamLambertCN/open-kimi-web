# 价格刷新连续性修复与 v2.1.1-r5 发布计划

日期：2026-09-29。兼容基线为 Kimi Code 2.1.1，补充用量定价自动匹配 v2 计划。

## 范围与证据

- 修复起点为 develop bb28a6e；main 与 r4 为 694d69a。
- r4 实际公共目录返回 7,932 项；13 个内置模型因同 ID 多渠道而全部失去隐式定价。
- 用户授权修复、发布，并移除 r1–r4 的旧 tgz 安装附件；不删除 Git 标签或整个 Release。
- 保留已有未跟踪文件和其他工作树，不读取真实用户会话、价格文件或凭证。

## 实现契约

1. 手动映射和手动单价始终最高优先，目录刷新不得覆盖。
2. 既有唯一匹配的默认目录选择单独保存，与用户确认的 mappings 分开。
3. 同键新价格优先；加入其它渠道不得让既有默认失效，不得静默更换渠道。
4. 目录项消失时保留最后有效项及阶梯价，来源必须明确表示旧目录价格，不冒充最新数据。
5. 默认选择经过持久化、重启、连续刷新仍有效；校验新增缓存字段并兼容旧缓存。
6. r4 已刷新成歧义目录的缓存，按内置已知模型及原目录键恢复默认来源，不将模糊候选用于计费。
7. 新出现且原选择不明的歧义模型继续给出建议并要求确认，不任取供应商。
8. 本次不改 UI 布局，旧价格提示复用来源字段；必要的文案修改须有针对性断言。

主要实现位于 `packages/launcher/src/usage/pricing.mjs`，可抽取独立辅助模块。
沿用现有数据投影、受限存储、无额外依赖和手写代码 130 字符限制。

## 验证契约

- 在现有 pricingStore/usage UT 与 launcher-usage IT 覆盖刷新前后费用、重复 ID、目录项缺失、
  手工覆盖、重启恢复、刷新失败、旧缓存升级；通过真实 HTTP 路由验证用户原始操作。
- 用 models.dev 和 OpenRouter 实际返回再次检查 13 个内置模型，不读取真实用户数据。
- 同步 launcher、插件和现有文档的 r5 版本入口；upstream 官方基线保持 2.1.1。
- 发布包括 develop 的自动匹配、批量确认、大列表分页和完整有序用量脚本 bundle。
- 运行 CI 同等命令：`corepack pnpm lint`、`corepack pnpm typecheck`、
  `corepack pnpm test:ut`、`corepack pnpm test:it`、`corepack pnpm test:pack`。
- 覆盖率门槛不降低；检查 `git diff --check` 和手写行宽。
- 项目无独立 build 命令，以 prepack/pack 为构建，验证实际待上传 tgz 的版本与价格刷新场景。

## 发布与安全边界

1. 用 privacy-check 检查待公开 diff、相对 main 的新增提交历史、实际 tgz 内容与清单、
   sourcemap、敏感路径及本次发布新增截图；不重复检查未变化的无关媒体。
2. 提交推送 develop，通过受保护 main 的 PR 与 CI 流程合并，不绕过保护、不强推。
3. 正式标签从通过验证的 main 创建，同步 develop；发布 GitHub Release 并上传 r5 tgz。
4. 回读核对标签提交、发布资产及版本；新包成功发布后才删除 r1–r4 的旧 tgz 附件。
5. 保留旧 Release 和 tag；r1 已撤回则记录不存在，不重新创建。
6. 核对 r5 可下载、旧包已移除，清理本任务临时进程与文件。
7. 报告版本地址、根因、验证、旧包移除情况；升级后须重启 launcher 并刷新页面。
8. 验证或发布受阻则明确报告未完成，不提前移除旧包。
