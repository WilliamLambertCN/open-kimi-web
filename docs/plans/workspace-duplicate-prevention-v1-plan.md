# 工作空间重复创建修复 v1

## 目标与边界

双端“新建工作空间”对已经登记的同一目录只提示已存在，不再创建额外工作空间。
继续使用官方工作空间接口，不删除、隐藏或合并已有条目，不迁移会话，不切换当前会话或清空输入草稿。
不升级官方 CLI，不重启生产服务，不改变目录信任或多目录工作空间配置。

## 依据与方案

准确官方 2.6.1 的 POST `/api/v1/workspaces` 每次生成新的 managed ID；只有携带相同 `idempotency_key` 才复用结果。
现有入口只防止一次提交尚未结束时的双击，没有查询已有工作空间，也没有携带幂等键。
隔离后端已复现：同目录两次无键提交产生两个 ID；四次并发同键提交只产生一个 ID。

- 提交前通过官方 GET 读取工作空间列表，发现同一根目录便返回“已存在”，不 POST、不选择任意旧条目。
- 保留复制路径时的外层引号处理；Windows 形状路径统一分隔符、大小写和尾部分隔符，POSIX 保留大小写及反斜杠。
  根目录保留身份，不按文件夹名称去重，不自行折叠可能涉及符号链接的 `..`。
- 新目录使用由目录身份派生、长度受限且带命名空间的稳定幂等键，交给官方后端处理并发与未知结果后的重试。
  不保存路径、工作空间 ID 或 token 到浏览器存储，不自动回退到无键提交。
- 列表读取失败或格式不可信时停止提交；保存结果必须包含有效 ID 且根目录与输入一致，不能误报成功。
- 复用现有双端对话框、主题、提交锁、取消和过期结果保护，添加中英“已存在”提示。
  路径输入关闭自动纠错和自动大写；状态仍使用可访问的实时提示。

目录身份比较不等于文件系统 realpath：符号链接别名和不同挂载点不在本轮合并范围。
历史重复项保持原样；新增入口不尝试修复官方数据库，也不保证绕过该入口的其它客户端不会主动建立同目录工作空间。

## 同版补充

- 新建弹层增加运行端文件夹浏览器，调用官方 GET `/api/v1/fs:browse` 按需逐层浏览。
  提供主目录、上一级、当前目录与子文件夹选择，保留粘贴路径；只在确认添加时登记工作空间。
  浏览不创建文件夹、会话或信任，关闭取消待处理读取，不缓存目录到浏览器存储。
- 修复手机会话设置中候选池入口的实际点击流程，以准确完整页面复现结果为依据，不猜测根因。
  保留候选、说明、草稿及原生设置；定向验证真实触摸、弹层生命周期和错误反馈。
- 桌面列表标题附近提供“平铺 / 按项目”两个快捷按钮，委托原生视图菜单切换。
  保留原入口的排序功能，不复制会话列表或只改存储伪装切换；活动状态跟随原生状态。
- 新界面沿用官方组件语义、主题变量和既有空间密度；双端、窄屏及实际受影响主题检查截图与可点击区域。

### 事件：同一目录被重复创建为工作空间

- 影响：双端从增强入口重复添加同一目录，会在官方列表产生多个条目。
- 触发条件：同目录再次提交，或两个页面同时首次提交；Windows 的大小写和分隔符差异也会触发。
- 根因：入口直接 POST，只有当前提交锁；官方无幂等键时每次产生新 ID，原测试只覆盖单轮双击。
- 证据：准确隔离后端的两次无键提交产生两个 ID，四次同键并发只产生一个；非数据库渲染误差。
- 修复：先读官方列表比较目录身份，新目录带稳定幂等键；失败保留输入，不擅自删除已有记录。
- 回归验证：新增重复、并发、未知结果后重试及路径身份测试，并完成真实后端和双端完整网页验证。
- 运维动作：更新后手动重启旧 launcher 并刷新网页；不迁移数据，不需要清空缓存。
- 剩余边界：不合并符号链接、挂载别名或历史重复，不接管其它客户端的主动创建；实体手机未直接验收。


### 事件：候选池弹层失败后入口无法重试

- 影响：原生弹层未成功打开，或被原生动作关闭后，入口可能一直没有反应。
- 触发条件：`showModal` 缺失、抛出，或原生 `close` 事件未同步到增强层；这些是本轮确认的失败路径。
- 根因：打开状态先于原生调用置位，异常没有回收；旧测试对弹层 API 只模拟成功，也未验证外部关闭。
- 证据：完整页面注入一次打开异常和缺失方法后可复现；修复后提示可重试，恢复方法后真实触摸可重新打开。
- 修复：失败释放状态、移除未打开的弹层并显示中英提示；原生关闭事件同步清理，不回显异常详情或修改候选配置。
- 回归验证：定向生命周期与观察器测试，以及 8 项真实页面失败注入和触摸重试通过；正常触摸矩阵未复现现场问题。
- 运维动作：更新后手动重启旧服务并刷新页面；未替用户升级 CLI 或重启运行实例。
- 剩余边界：实体设备那次无响应的根因仍未确认，不把失败注入当作现场根因证明。
