# Open Kimi Web 2.4.1-r2 发布计划

本计划整理新版发布范围。本次将已完成的本地改动整理为 `2.4.1-r2`，官方兼容基线仍为 `2.4.1`。
本计划承接此前功能计划，不把历史阶段的“不提交／不发布”误当作本次限制；真实会话、凭据和临时测试资料始终不公开。

## 发布范围

- [低带宽大会话优化](large-session-low-bandwidth-v2-plan.md)：主会话先加载最近一轮，旧历史继续使用官方分页。
  只对增强页面的精确官方 `2.3.1`／`2.4.1` 生效；没有用户偏好时默认折叠工具活动，不修改已有选择。
- [排查慢加载的日志](large-session-debug-log-v1-plan.md)：`--debug`、`--debug-log` 和环境开关，默认关闭。
  记录脱敏阶段统计，不保存正文、凭据和真实路径，也不开启官方调试接口。
- [安装到桌面](pwa-install-v1-plan.md)：双端入口、安装清单和图标；需要浏览器支持及设备信任的 HTTPS。
  不提供离线聊天，不另存登录凭据；已有实图和浏览器验收不等于实体手机安装验收。
- 保留普通 `kimi` CLI 使用习惯：非 web 调用原样交给官方，不用网页选项校验拦截同名参数或提示词。
- 简化根 README，保留原图并新增两张安装面板实图，保留两段在线安装命令并更新为本次版本。
- 纳入为上述验收修复的测试同步／清理问题，不夹带原 `.tmp/`、缓存或其它项目内容。

不修改官方安装版本、不升级用户实际 CLI、不修改用户 PATH 或会话，不自动重启生产。
不删除或移动任何旧 tag、Release 或资产，不发布到 npm registry，不重写共享分支历史。

## 顺序

1. 确认远端 main／develop 与最新版本，设置 `packages/launcher/package.json` 为 `2.4.1-r2`。
2. 更新当前安装链接、根与 launcher README、项目 Skill、CHANGELOG、UPSTREAM，历史版本证据保持原样。
   根 AGENTS 链接本计划；新安装命令仍解析真实 tag SHA 并下载同 SHA 脚本，不伪造提交。
3. 有针对性审查拟公开文件、提交身份、最终 tgz 清单与内容，排除个人路径、真实会话、日志、缓存和 sourcemap。
   已查看且未变更的图片不重复截图；核对新增图片与已审查资源一致。
4. 生成实际 `open-kimi-web-2.4.1-r2.tgz`，检查版本、必需模块、manifest、图标及公开目录。
   复用此前 Windows 功能与视觉验收和最后一次 CLI 定向验证；不重跑无变化的浏览器或整套安装矩阵。
5. 使用已确认的 GitHub noreply 身份提交 develop，推送并建立到 main 的 PR。
   必须通过仓库现有 CI：lint、typecheck、带覆盖率的 UT／IT、test:pack。失败先修，不降低门槛。
6. 正常合入 main，确认 main CI；只在通过的 main 提交创建新 tag，上传已核对的正式 tgz，设为最新正式 Release。
7. 核对公开版本、tag、下载资产与本地包一致；用上一版本更新检查确认能发现 r2，核对安装入口使用同一 SHA。
8. 正常同步 main 到 develop；保留用户原有未跟踪内容，清理自有临时进程，简要报告发布和未验证边界。

## 交付限制

- 不保证任意 200–500 MB 会话或巨大单轮都能秒开；日志只能帮助区分服务端等待与传输，不测浏览器渲染。
- 先前授权真实会话的测试只保留无正文统计，既有匿名验收记录不是新的用户会话读取授权。
- 实体 Android／iOS 安装、各浏览器凭据共享及所有平台安装组合尚未全面验证。
- 发布不会自动更新或重启用户正在运行的服务；升级后自行重启并刷新网页。
