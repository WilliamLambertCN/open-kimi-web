# 双端会话菜单：分叉与手机置顶 v1

范围来自用户明确要求：手机、电脑会话列表的三个点菜单提供 Fork／分叉；手机再补置顶／取消置顶。
只改本地代码并验收，不提交、推送、发布，不重启生产，不覆盖工作树已有 CA 修改。
本计划经工具自动放行不代表用户逐项审阅；实施基线由 AGENTS 链接。

## 已核事实

- 官方精确 2.3.1 和 2.4.1 桌面 SessionRow 已有右键菜单，含分叉和置顶，但没有会话行三个点。
  工作区的 .gh-more 不是会话操作；桌面平铺行也不一定有 data-session-id。
- 手机 .sheet-panel 的 .mlist 内 .srow > .kb 打开 .kmenu，只有重命名、归档、删除。
  手机 DOM 没有 session ID；不能按标题、相对时间或顺序猜写操作对象。
- 官方 Fork 使用 POST /api/v1/sessions/{id}:fork，空 JSON body；成功须 code=0 且新 id 与源不同。
  正式 2.4.1 会拒绝忙碌／别进程占用；保留原会话，不自动重试、终止、信任或接管。
- 官方置顶仅存浏览器来源的 kimi-web.pinned-sessions ID 数组，不是工作区置顶或后端元数据。
  修改 storage 不更新原生内存，伪造 storage 事件也无效；需要一次正常重新载入同步，不能调用 Vue 私有状态。
- 官方手机列表没有按 pin 展示；必须补清晰的已置顶区，不能只保存偏好而不显示效果。

## 实施

1. 新增独立菜单、API 与 pin 文件，复用 locale.js。
   在 officialPresentation.mjs 注册资产，并更新 launcher-official asset IT 与既有注入共存计数。
   不改官方编译 bundle、后端或传递依赖，不加入另一个会话／置顶存储。
2. 桌面：给 .side 会话 .se 的 action 区追加三个点，点击只派发该行的原生 contextmenu。
   使用官方菜单的 Fork／Pin、错误处理与精确闭包身份；支持分组、平铺、已置顶、长短标题、键盘与触屏点击。
   不改工作区菜单、不自动选中源会话、不重复新增已有原生 Fork。
3. 手机：在精确 switcher 的会话菜单里增加分叉和置顶操作，不改已有重命名／归档／删除节点及监听。
   为写操作取得精确身份：自有置顶行使用精确 ID；所有原生行（包括 .cur）均显式调用捕获行的原生选择，
   从该次选择后的 canonical /sessions/{id} 路由确认源 id；不能只把 .cur 与选择前的 URL 拼在一起。
   原生当前行仅在同步选择后 URL 未改变时沿用该路由；冷导航等待时必须先由原生选择纠正 URL，避免操作另一会话。
   此降级会先打开源会话并关闭列表，实施和验收如实记录，不冒充无选择副作用的后台操作。
   Fork 保留同源 Bearer 和官方客户端身份头，仅内存观察；只发一次，成功后用公开 route 导航新会话。
   HTTP／业务错误、网络超时／结果未知和格式错误均本地化提示；不自动重试，避免重复分叉。
4. 手机 pin 沿用官方 ID storage，只保存 ID，写前重新读取并保留其他项；存储失败明确提示。
   先验证官方草稿保存正常，再一次重新载入同步原生 pin 状态；恢复会话列表，显示已置顶区和取消置顶入口。
   pin／unpin 在原生选择前和刷新前检查附件准备状态；旁观同源正式文件上传的 fetch／XHR，仅记在途计数，
   上传或本地准备未结束则提示稍后重试，不切会话、不保存 pin、不自动刷新，避免中断未发送附件。
   原生菜单与自有已置顶菜单互斥，打开置顶菜单前用原生三点动作关闭已开的原生菜单，不移除 Vue 节点。
   已置顶区仅使用正式 API 中的精确 ID／标题投影，可在已知 pin ID 时按需 GET 对应会话，不读取全文。
   支持平铺及分组；取消置顶立即移除该偏好，不归档／删除；不误用 pinned-workspaces。
   不承诺跨手机、电脑或不同 IP 来源同步。
5. 样式以官方按钮／菜单、44px 手机触控尺寸和主题 token 为基线；小屏／底部菜单限制高度并可滚动。
   只观察 sidebar／switcher／menu 的相关变化，幂等写入，不在聊天流每次变化时全局重扫。

### 事件：三个点菜单缺少分叉，手机无法查看和操作已置顶会话

- 影响：手机菜单只有重命名、归档、删除；电脑需要知道右键入口，手机也没有显示已置顶会话的区域。
- 触发条件：准确官方 2.3.1／2.4.1 的会话列表，手机或电脑使用三个点操作。
- 根因：桌面分叉只在原生右键菜单；手机菜单没有这两个动作，也没有按官方 pin 偏好显示的区域。
  旧测试没有覆盖新增的三个点入口，无法证明这两个操作可用。
- 证据：两版官方 DOM、正式 Fork 请求及 pin storage 语义已核对；首次完整 app 验收发现键盘和主题定位的遗漏。
  jsdom 的旧短屏样例只返回菜单高度，没模拟主题导致的 9px 定位偏移；原生菜单本身也没有箭头／Escape 处理。
- 修复：桌面三点复用原生菜单，手机增加精确身份的正式 Fork，以及沿用官方 ID 偏好的置顶区与取消置顶。
  不改后端、信任、会话锁或工作区置顶，不自动重试；通过当前行原生选择修正路由竞态，等待附件上传再允许 pin 刷新。
- 回归验证：本地功能验收完成；正式后端 23／23、193 定向 UT、5 资产 IT、lint／typecheck 通过。
  首轮界面失败保留，窄屏边界与桌面键盘均修后定向补验，最后两版 Tab／Shift+Tab 18／18；不以单元测试冒充实图。
- 运维动作：本轮不重启正在运行的服务，不提交或发布；新资源要在服务使用本地改动并刷新后才会生效。
- 剩余边界：置顶保存在当前浏览器的同一来源，不跨设备或 IP 同步；实体手机、系统软键盘及任意大会话未全面验证。
