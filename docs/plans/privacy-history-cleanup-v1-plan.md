# 公开文档与提交历史隐私清理 v1

## 目标与范围

清理公开仓库 Open Kimi Web 中的个人作者邮箱、内部网络信息和不必要的个人操作记录。
保留功能代码、测试、安全边界、实现决策和有工程价值的验证结论，不把隐私清理当作功能发布。

- 当前文件：精简 `AGENTS.md` 的操作流水，保留维护规则与计划链接；计划中不再记录私人地址、原话和个人会话精确测量。
- 历史对象：在隔离副本中清理上述文档，统一相关 author、committer 和 annotated tag 的公开身份。
- 远端引用：核对全部公开分支和 tag；只推送明确列出的引用，使用准确旧 SHA 的 `force-with-lease`。
- 不操作官方 MoonshotAI 仓库，不重启服务，不升级 CLI，不发布新版，不顺带推送本地 2.6.1 功能。
- 如需临时调整分支保护，先保存原设置，推送后立即恢复并回读核对；不长期取消门禁。

## 实施顺序

1. 保存远端引用、保护设置、Release 元数据和本地工作树备份；备份只存忽略目录，不推送。
2. 核对实际文件、提交身份、已删除文件及 tag；保留明确的 fixture、通用示例和必要源码，不机械删除关键词命中。
3. 清理当前文档，并在隔离副本对历史使用相同规则。保留提交拓扑和功能差异，记录旧、新 SHA 对应关系。
4. 比较所有公开分支及 tag 的功能文件；除明确改成文档示例地址的测试数据外，代码和图片必须原字节不变。
5. 对清理后的准确交付执行标准检查；先尝试原有流程，确需临时调整保护时限定在推送窗口。
6. 安全更新引用，恢复保护。核对正式 Release、原下载包和在线安装入口；不替换无隐私问题的发布包。
7. 将本地未发布分支同步到清理后的历史，保留全部未提交功能改动；不使用破坏性 reset 清理工作树。

## 验证与边界

- 检查清理后可写公开引用中不再包含目标邮箱和私人记录；检查当前文档链接、行长及 `git diff --check`。
- 代码、测试、图片及锁文件以原字节比较确认未被误改；只对确有变化的测试数据补定向验证。
- 历史重写会改变提交 SHA 和 tag 指向。版本名及发布包不变；使用旧克隆的协作者需要重新克隆或谨慎迁移本地工作。
- GitHub 的只读 PR 引用、旧 SHA 页面、缓存、fork 和他人克隆不一定随推送删除；需要 GitHub 支持处理的部分单独报告。
- 未发现真实凭据时不要求无依据地轮换密钥；若发现真实凭据，先通知撤销或轮换，再继续清理。
